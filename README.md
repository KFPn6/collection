# collection

いうたさんが所有しているコレクション（ポケモンカードなど）の台帳です。
チャットで「○○を登録して」と頼まれたら、この台帳にアイテムを追加・更新します。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `data/collection.yaml` | 正本。追加・更新はここを編集する |
| `README.md` | 項目の説明と、人が見る一覧表 |

仕組みはこれだけです。データベースやアプリはありません。

## 項目

| キー | 項目 | 説明 |
| --- | --- | --- |
| `id` | ID | 通し番号。既存の最大値に 1 を足す。あとから変えない |
| `category` | カテゴリ | ゲームの名前。例: ポケモンカードゲーム、ONE PIECE CARD GAME |
| `name` | 商品名 | 公式表記が分かるときは公式の名前を使う。シングルカードでは `card_name` と同じ |
| `kind` | 種類 | 例: 構築済みデッキ、拡張パック、デッキセット、カードセット、スペシャルBOX、シングルカード |
| `card_name` | カード名 | シングルカードだけ。商品では書かない |
| `collector_number` | 収録番号 | シングルカードだけ。例: `118/081` |
| `rarity` | レアリティ | シングルカードだけ。例: `MUR` |
| `set_name` | 収録パック | シングルカードだけ。例: 拡張パック「アビスアイ」 |
| `quantity` | 数量 | 持っている個数（整数） |
| `condition` | 状態 | `未開封` または `開封済み`。不明なら `null` |
| `release_date` | 発売日 | `YYYY-MM-DD`。シングルカードでは収録パックの発売日。不明なら `null` |
| `list_price` | 定価（税込） | 希望小売価格。円の整数。シングルカードなど定価がなければ `null` |
| `purchase_date` | 購入日 | `YYYY-MM-DD`。不明なら `null` |
| `purchase_price` | 購入価格 | 実際に支払った金額。円の整数、税込。不明なら `null` |
| `store` | 購入店 | 買った店の名前。不明なら `null` |
| `buyback_shop` | 買取店（売却予定先） | 売る予定の店の名前。未定なら `null` |
| `buyback_url` | 買取ページ | その店の、この商品の買取ページ。未定なら `null`。買取価格は変動するので入れない。価格を残すときは確認日とセットで `memo` に書く |
| `memo` | メモ | 自由記述。なければ `null` |
| `official_url` | 公式URL | 公式の商品ページ、またはカード詳細ページ。なければ `null` |
| `registered_on` | 登録日 | この台帳に登録した日。`YYYY-MM-DD` |

不明な項目は空欄（`null`）にします。「未確認」という文字は入れません。

## 登録のしかた

1. `data/collection.yaml` の `items` の末尾に、上の項目をそろえた1件を足す。シングルカードなら `card_name`、`collector_number`、`rarity`、`set_name` も書く。`name` にはカード名を入れる。
2. 発売日と定価は、分かる範囲で公式ページを見て、違えば公式の値を使う。ポケモンカードゲームは [pokemon-card.com](https://www.pokemon-card.com/) の商品ページやカード検索、ONE PIECE CARD GAME は [onepiece-cardgame.com](https://www.onepiece-cardgame.com/) の商品ページやカードリスト。ページの URL を `official_url` に残す。シングルカードに定価がなければ `list_price` は空欄にする。
3. 下の一覧表に同じ内容の行を足す。商品とシングルカードで表を分けている。YAML が正本で、表は見やすさのためです。

更新するときは、同じ `id` の項目と表の行を直します。
